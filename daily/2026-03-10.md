## 🎯 Focus Today

Understanding const-correctness in C++.

---

## 📚 What I Learned

Today I ran into a compilation error when trying to call a non-const member function from a const member function within the same class.

Example:

```cpp
class Example {
public:
    void update() {
        value++;
    }

    int getValue() const {
        update(); // ❌ compile error
        return value;
    }

private:
    int value = 0;
};
```

The compiler complains because `getValue()` is declared as `const`, meaning it promises **not to modify the object's state**.
However, `update()` is a **non-const member function**, which potentially modifies the object.

Inside a `const` function, the `this` pointer becomes:

```cpp
const Example* this;
```

Therefore, only **const member functions** can be called.

---

## 💻 Tech Notes

Key concept:

* In a `const` member function, the object is treated as **read-only**.
* The compiler enforces **const-correctness**.

Possible fixes:

### Option 1 — Make the function const

```cpp
int getValue() const {
    return value;
}
```

### Option 2 — Mark the called function as const

```cpp
void update() const; // only if it doesn't modify state
```

### Option 3 — Use `mutable` (rare cases)

```cpp
mutable int cache;
```

Used for **logical constness**, e.g. caching.

## 🧠 Thoughts

This error reminded me that C++ const correctness is not only about preventing modification but also about expressing **intent** in the API.

A well-designed class should clearly distinguish between:

* functions that **read state**
* functions that **modify state**

This also improves code safety and readability.
